# 进阶操作

面向已经能把日常对话跑起来的用户，讲清那些「知道在哪，但不知道规矩」的地方。

## 1. 提示词与变量

设置 → 提示词与人设里可以改基础提示词。提示词里可以写这些变量，发请求前会被替换成「我」页里的资料；没填的替换为空串：

| 变量 | 来源 |
| --- | --- |
| `{user_name}` | 昵称（最长 40 字符） |
| `{user_gender}` | 性别（未设置/男/女/其他） |
| `{user_birthday}` | 生日（YYYY-MM-DD） |
| `{user_occupation}` | 职业（最长 60 字符） |
| `{user_extra_note}` | 补充说明（最长 500 字符） |

每次保存提示词会生成一个新版本（v1、v2…），旧版本保留可回溯；只改描述不会产生新版本。
调试面板可以看到最终拼装结果，但任何疑似凭证的内容会整段隐藏。

## 2. 两种模式的区别

| | 问答模式 | 聊天模式 |
| --- | --- | --- |
| 会话数 | 多条，可置顶、搜索、删除 | 始终只有一条活动会话 |
| 界面 | 会话列表 + 对话页 | 我 / 设置 / 聊天 三栏 |
| 记录 | 各自独立，切换不改写对端 | 同左，未提交草稿互不共享 |

首次启动按设置里的默认模式进入；连续切换不会丢草稿、滚动位置与选中的人设。

## 3. 撤回与修改

- 发消息后 2 分钟内（设置里可调）可以撤回：原消息正文替换为「该消息已被撤回」，不再进入后续上下文；界面提供短时撤销入口，撤销会恢复正文与状态。
- 超过时间窗仍可**修改**消息：修改会写入编辑时间并保留首次原文。
- 改过的消息在「消息操作」里还有一项**撤销修改**：正文回到首次原文，编辑时间与原文字段一起清空（撤回的撤销是另一条路径，两者互不覆盖）。
- 撤回与修改只影响本地记录，已经发出去的请求无法收回。

## 3.1 停止生成与重新生成

- 生成过程中输入框右侧按钮变成「停止」，点一下即中断流式接收；已发出的用户消息保留，不回滚。
- 聊天页顶部「重新生成」会取最后一条回复重跑一次：旧回复被标记为已取代（不再进入上下文），但仍留在库里与导出文件中，可回溯。

## 4. 导出与导入

导出（JSON）字段：`format`（固定 `chat_record`）、`schema_version`、`exported_at`、`source_mode`、`conversations`、`messages`、`checksum`（正文哈希）。

导入顺序：校验格式 → 校验版本 → 校验 checksum → 预览会话数与消息数 → 选冲突策略 → 事务写入（失败整体回滚）。

| 冲突策略 | 会话 id 冲突 | 消息 id 冲突 |
| --- | --- | --- |
| 按 id 去重（默认） | 跳过 | 跳过 |
| 覆盖同名 | 用导入内容覆盖 | 覆盖 |
| 保留双方 | 换新 id 新建 | 换新 id 追加 |

Markdown / 纯文本导出只用于阅读，不能导入。备份包与导出包是两个命名空间，解析器互不兼容。

导出浮层还能选范围与内容：**当前会话 / 全部会话 / 近 7 天**，以及是否**包含头像图片**（含头像时 JSON 尾部多一个 `avatars` 数组，逐张给相对路径、SHA-256 与 Base64 正文）。
范围按消息创建时间过滤：区间内一条消息都没有的会话整条不导出，不会留下空壳。

## 4.1 数据管理（备份 / 恢复 / 清理）

设置页「数据管理」：

- **立即备份**：把数据库、头像、插件数据与一份带逐文件 SHA-256 的清单打成标准 ZIP，放在数据目录的 `backups` 下。
  创建前先做 WAL 检查点与 `PRAGMA quick_check`，不通过就拒绝备份。
- **恢复备份**：默认取最新的备份包，先整包校验再解压到 `backups/restore-<时间戳>`，覆盖数据库与头像/插件目录；失败不动现有数据。
- **清理旧备份**：保留最近 3 个，其余删除。

## 4.2 头像

「我」页的「编辑资料」可以选本地图片：导入时用 GDI+（Android 用系统相册）解码、等比缩到最长边 512 像素、
重新编码成 JPEG 存进数据目录的 `avatars/`，资料里只保存相对路径，因此数据库迁移/备份搬家不会失效。
保存失败时保留原头像不变。

## 4.3 分页加载

会话默认只加载最近 100 条；消息区顶部的「加载更早」每次向上翻一页，直到没有更早的消息为止。
这样万条消息的会话也不至于一次性全读进内存，翻页耗时按单页计。


## 5. 模型与费用

两个内置模型：`deepseekv4.1flash`（短轮次快响应）与 `deepseekv4pro`（长文本复杂推理）。
模型按会话保存，切换只影响后续请求。新增模型只需在数据目录放一份 `models.json`，启动时读取，不改核心代码：

```json
{
  "models": [
    {
      "id": "my-model",
      "name": "我的模型",
      "summary": "私有部署或新版本",
      "context_tokens": 65536,
      "price_in_micro_per_mtok": 2000000,
      "price_out_micro_per_mtok": 8000000
    }
  ]
}
```

`id` 与内置模型同名时覆盖内置定义；最多 16 个；清单不合法时整份忽略并写诊断日志，内置模型不受影响。

费用分两项展示：账户接口返回的可用余额（含未出账金额）与本地账本按请求累计的消耗，两者并列并标注来源。
查询失败时保留上次结果并标注过期时间；低于阈值时设置页出现横幅并通知一次。

## 6. 更新与数据保护

1. 启动时与固定周期检查更新（可关）；
2. 非阻塞提示：立即 / 稍后 / 跳过该版本；
3. 下载支持断点续传；
4. 应用前校验签名、SHA-256 与版本号；
5. **更新前必须完成数据一致性检查与目录外完整备份，备份成功是写入的前置条件**；
6. 首次启动按 `schema_version` 顺序迁移，迁移前再备份一次，失败自动回退；
7. 安装：把当前安装目录复制到 `backups/app-<时间戳>` 作为回滚点，然后调用安装包 `/S /D=<安装目录>`，
   失败则整树回滚到更新前的版本；卸载默认保留用户数据。

## 6.1 插件

设置页「插件」列出已安装插件、一键启用/禁用、用新的 `plugin.json` 更新到新版本。
导入前会先把来源、名称、标识、版本、作者、权限、扩展点、入口与入口哈希摊在确认框里，确认后才落地；
同名插件已安装时按钮变成「覆盖安装」，不会静默替换。清单里给了 `sha256` 就校验入口文件哈希，不符即拒绝安装。
插件进程受内存（128MB）与 CPU（5 秒）上限约束，超限或超时由宿主终止并禁用该插件，主程序继续运行。
「扩展点面板」会把 `ui.panel` 的 `describe` 请求发给所有启用且声明了该扩展点的插件（插件跑在独立进程，超时会被终止并禁用）。
提示词片段 `prompt.fragment` 在每次组装系统提示词时自动拼进去。

## 6.2 双端配对与实时同步

首次配对（设置 → 配对管理）：

1. 两台设备各自打开「配对管理」，都能看到自己的 6 位配对码（100000~999999，5 分钟内有效，输错累计 5 次即作废重来）。
2. 一台点「开始监听等待连入」，另一台在「对端局域网地址」里填对方地址后点「连到该地址并配对」；也可以点「发现同网设备」从列表里挑。
3. 连接方填**对端**的 6 位码，被连接方填**对端**的 6 位码——两边填的都是对方生成的码，双向都对上才建立配对。
   配对完成前不交换任何业务数据。
4. 配对成功即进入「同步中」，实时同步默认开启；共享密钥写进系统安全存储，界面上看不到明文。

日常规则：

- **暂停**只停新事件发送，已经入队的事件不会丢；恢复后按 event_id 续发，不必重配。
- 同一时刻只与一个已配对设备同步；换设备先「解除配对」，再和新的那台配。
- 同步范围：用户资料、人设、会话、消息、提示词版本、设置白名单项、插件清单。
  插件二进制、API Key 等凭证、用量流水、日志、备份包**不参与**同步。
- 冲突谁赢：逻辑时钟大的赢，相等时比设备标识的字典序；输的一方原始内容会留一份副本，配对页「查看冲突（N）」里能看到条数。
- 顺序只认逻辑时钟，墙钟（消息时间）只做展示，所以两台设备时钟不一致也不会打乱聊天记录顺序。
- 解除配对会删掉共享密钥与配对记录，但**两端本地数据都保留**。
- 跨网段、开了防火墙或者不在同一局域网时，局域网通道连不上；这种情况用设置里的记录导出/导入迁移历史。

## 6.3 首次启动要按什么顺序配

从 1.3.0 起，第一次启动的顺序是固定的：**先填 API Key，再选默认模式**。凭证没写进系统安全存储之前进不了主页，
这样不会出现「模式选完了却发不出消息」。只想先看界面可以点「演示模式」——演示模式不发任何网络请求。

## 7. 性能与仪表

性能预算（桌面 / 移动）：冷启动 2.0s / 2.5s、常驻内存 240MB / 180MB、模式切换 200ms / 220ms、三栏切换 150ms / 160ms、首段回复 2.0s、万条分页 300ms / 350ms、万条导出 2.0s / 2.5s、安装包 80MB / 60MB。

- `aic.exe bench` 跑分页、导出与内存的实测值；
- `aic.exe verify` 的 FR-24 会把实测值与预算逐项比对，任一项超出即失败；
- 连续两版超出任一目标应阻断发布，劣化超过 10% 视为回归。

## 7.1 未保存改动的保护

表单（人设、API Key、资料、改名等）里改过但没保存时，点取消或按 Esc 不会直接丢掉输入，
而是先弹一次「放弃未保存的修改？」确认，确认后才关闭。聊天输入框的草稿不属于这一类：
切换模式或三栏时草稿一律保留，不会被清掉。

## 8. 便携模式

设置环境变量 `SAI_DATA_DIR` 指向任意目录，数据库、插件、头像、备份都会放在那里，适合放 U 盘或多套配置隔离测试。
